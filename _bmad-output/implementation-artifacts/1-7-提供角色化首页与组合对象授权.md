## Story

作为平台用户，
我希望登录后进入与当前有效职责匹配的单一首页，只看到并只能访问当前角色、组织、责任关系、有效任务或代办允许的入口、对象与动作，
以便无需切换或猜测身份即可安全开展工作，并确保职责变化、撤权、过期或冲突在下一次请求立即生效且不泄露对象信息。

## 业务与交付价值

- 将“已认证”升级为“只能在当前职责范围内工作”，完成 Epic 1 的角色入口和对象授权主干。
- 由一个冻结、可验证的 RFP 判定器统一七类岗位的角色、对象、动作与 scope 语义，避免后续模块各自发明权限逻辑。
- 为 Story 1.8 的字段级实际投影、Epic 3 的关怀、Epic 5 的协同、Epic 6 的驾驶舱和 Epic 7 的移动端提供公共授权边界。
- 在本 Story 触及的 API、路由和对象判定面证明越权成功数为 0；不得借此提前宣称导出、移动端或全渠道 NFR-16 已全局关闭。

## Story 元数据与实施边界

- **显式依赖：** Story 1.6c（已完成）。1.6a/1.6b、1.2、1.3—1.5 是必须复用的既有能力，不新增 `dependsOn`。
- **需求所有权：** FR-3、FR-5 的唯一 full owner；FR-2/NFR-27 的 current-scope/downstream activation contributor；NFR-16 的本 Story 授权面 contributor。
- **受控 `readyWhen`：** `RFP-1.0.0` 七角色对象/动作/scope 表、冲突算法、字段矩阵及 `RFP-FIXTURE-1.0.0` 已批准；必须复用 1.6c 即时 current-scope 与 invalidation fence。Task 1 合同 lock/checker 未通过前，不得编写 Tasks 2—8 的产品实现。
- **Sprint 状态含义：** `ready-for-dev` 只表示本 Story 文件与实施上下文已创建，不表示 RFP 运行实现、证据或测试已完成。
- **默认方案：** 逐请求组合权威身份、当前责任 scope、对象 owner 提供的 scope evidence 与 1.6c fence；不新建事件驱动授权读模型。因此默认不新增 consumer、不伪造 watermark，也无需为授权投影新增数据库 migration。
- **未来对象事实：** 当前除审计检索外，多数业务对象模块仍是骨架。本 Story 交付真实、通用的授权引擎、生产审计检索授权与角色化壳；Candidate、Clue、Transfer、Report、DQ、Job 等仅作为批准的 conformance fixtures，不得伪造成生产对象、待办或运行证据。

### 本 Story 包含

1. 冻结 `RFP-1.0.0`、字段矩阵、默认首页投影、错误语义、审计词汇和 `RFP-FIXTURE-1.0.0` 的机器可读合同、schema、digest lock、正反 fixtures 与 checker。
2. 在 `identity-access` 新增独立对象级组合授权公共端口与应用服务，复用当前权威身份、组织、责任 scope、可信时间、policy version 和 invalidation fence。
3. 交付服务端计算的当前授权壳投影：一个默认首页、仅已授权且真实安装的菜单/入口、依赖状态与版本摘要；前端不提供角色切换。
4. 将现有审计检索从 conformance/dummy 授权接到真实 RFP 判定，并以 audit 1.4 successor 保存允许、拒绝和依赖失败证据。
5. 对受保护对象实现服务端每请求授权；对写命令提供提交前按 current relation/grant/policy/objectVersion 重检的公共 guard。
6. 提供统一不泄露的无权限/不存在响应、依赖失败状态、会话恢复、内存态清理、无障碍与响应式 UI。
7. 交付合同、领域、PostgreSQL、HTTP/security、前端、Playwright、隐私、并发、回归和发布证据。

### 本 Story 不包含

- `DelegationGrant` 的创建、审批、签发、撤销、到期调度或状态机；归 Story 3.9c。本 Story 只消费已证明有效的 grant，并验证它不能扩权。
- 公共任务/消息领域、真实待办聚合或回写；合同底座归 Story 1.9，生命周期归 Story 5.5。
- 辅导员 Top-k 工作台、学院业务总览、协同工单、驾驶舱指标、数据质量或技术运行的真实业务内容；分别由其 owner Story 实现。
- 导出申请、生成、下载重检与撤销，App/WebView 真机或跨端能力。
- 运行时 RFP 编辑页面、客户端角色模拟、原型的 `all|college|own|none` 粗粒度权限或原型蓝绿品牌壳。
- 新增 Kafka、Redis、JPA、Quartz、独立授权服务或持久化客户端授权缓存。

## Acceptance Criteria

### AC-1.7-HAPPY：七角色完整对象授权 oracle（受控原始 AC）

**Given** `RFP-FIXTURE-1.0.0` 固定七个主体、`CASE-A/B`、R2 对 `CASE-A` 的 `WORKITEM-A`、`TRANSFER-A/B`、`REPORT-COL-A/SCHOOL`、`RULE-1`、`DQ-A/B`、`JOB-1` 与固定 `serverNow`<br>
**When** 按 `roleId × objectClass × scopeRelation × actionId` 运行表驱动授权，并运行多角色和未知动作场景<br>
**Then** R1—R7 的允许/拒绝结果逐项等于批准 oracle；R2 只有借助 `WORKITEM-A` 才能对 `CASE-A` 执行最小 `care.read`，无 workItem 必须拒绝<br>
**And** R1+R2 对同一 object/action 采用最严字段模式；R1+R7 中没有 care 权的 R7 不得降低 R1；字面含 `/` 的 action、未知 `care.delete`、缺策略或职责冲突全部拒绝<br>
**And** `DelegationGrant` 采用 `[startAt,endAt)`，提交前重检 relation/objectVersion；越界和不存在使用相同 status/code/envelope，失败不泄露存在性并保存最小拒绝审计；本 AC 必须由完整 RFP 引擎证明，不能用 1.6c current-scope 或 conformance fixture 冒充运行授权。

### AC-1.7-ROLE-HOME：服务端生成唯一角色首页和导航

**Given** 当前主体已认证且权威身份返回一个或多个有效 R1—R7 角色包<br>
**When** Web 壳读取当前授权投影<br>
**Then** 七个单角色默认落点固定为 R1 关怀工作台、R2 学院治理、R3 规则与运营治理、R4 校级驾驶舱、R5 协同工单、R6 数据质量、R7 技术运行面板<br>
**And** 多角色只产生一个当前身份上下文和一个默认首页，优先级固定为“待处理责任任务 > 治理/质量任务 > 汇总态势 > 系统管理”；同层稳定 tie-breaker 冻结为 `R1 > R5 > R3 > R6 > R2 > R4 > R7`，其来源标记为本 Story 的确定性实施细化，变更须发布 RFP successor<br>
**And** 只返回服务端已授权且真实安装的 `menuItems/entryCapabilities`；未安装 provider 显示诚实的 `not-installed/unavailable` 状态或隐藏，不得用“0 条待办”、mock 数据或假按钮冒充能力；浏览器无角色切换控件。

### AC-1.7-COMPOSED-DECISION：组合角色、替代 scope anchor 与字段摘要

**Given** 请求包含当前 actor/session、单一展开后的 `actionId`、受控 `objectClass`、不透明 object token/digest、期望 `objectVersion` 和对象 owner 提供的 scope evidence<br>
**When** 组合授权服务判定请求<br>
**Then** 顺序固定为：验证 effective RFP → 选出 object/action 匹配且 scope predicate 成立的角色包 → 合并 allow → 应用 applicable explicit deny/职责分离 → 仅对实际授权该 object/action 的角色包按 `H > M > C` 取最严字段摘要<br>
**And** 组织、当前责任关系、明确 workItem、当前分配 TransferOrder、ownerBinding 和有效 DelegationGrant 是按对象类型选择的替代 anchor，不要求全部求交；未知角色、对象、scope relation、字段、action、policy/IAM/可信时间不可证明一律 fail closed<br>
**And** R2 不获得“本学院全部个案”，R4 永不个体下钻，R5 仅在当前 TransferOrder、有效任务窗与 purpose 内授权，R6 仅 owned source，R7 仅技术对象且不得自授业务权；RFP allow 不能绕过 HRAP。

### AC-1.7-RFP-CONTRACT：RFP 合同、动作与字段矩阵不可漂移

**Given** 构建、启动或请求路径加载 role-field policy<br>
**When** schema、policyVersion、fixture digest、role/object/action/scope/field allowlist 或 HRAP 映射被校验<br>
**Then** 只接受下述批准矩阵和单一展开 action；任何缺失、未知、digest 不匹配、旧版回滚、字面斜杠或破坏性未批准版本都使运行状态 unavailable 并 fail closed，旧合同与 lock digest 保持不变<br>
**And** 构建/发布 manifest 记录精确 RFP、fixture 与 audit successor 版本；生产授权不可从前端 route、菜单、OIDC 展示 claims 或原型常量反推。

批准对象/动作/scope 表：

| 角色包 | 对象与替代 scope anchor | 展开后的动作 |
|---|---|---|
| R1 `COUNSELOR` | 当前权威责任或有效 grant 内的 Candidate/Clue/CareAction/Observation/Task；本人发起 Transfer；本人基础 scope 的 DelegationGrant | `care.read`、`candidate.review`、`clue.follow-up`、`observation.manage`、`transfer.submit`、`transfer.read`、`transfer.resubmit`、`delegation.issue`、`delegation.revoke`（后两项另过 HRAP） |
| R2 `COLLEGE-MANAGER` | 本学院聚合；显式 `WORKITEM-A` 对应个案的最小投影 | `aggregate.read`、`aggregate.export`、`care.read`、`governance-action.record`、`governance-action.manage` |
| R3 `STUDENT-AFFAIRS` | 校级 Rule/Tag/Program/Governance/Aggregate；个案必须有显式治理 workItem | `governance.read`、`governance.edit`、`governance.review`、`governance.publish`、`governance.rollback`、`whitelist.change`、`bulk.execute`、`aggregate.read`、`aggregate.export`、`governance-action.record`、`governance-action.manage`、`audit.search-business-metadata`、`sensitive-export.create`、`sensitive-export.download`（后两项另过 HRAP） |
| R4 `SCHOOL-LEADER` | 校级/学院聚合，禁止 case/individual drill-down | `aggregate.read`、`aggregate.export`、`governance-action.record`、`governance-action.manage` |
| R5 `COLLABORATOR` | 当前分配、处于有效任务窗且 purpose 匹配的 TransferOrder | `care.read`、`transfer.read`、`transfer.accept`、`transfer.process`、`transfer.request-supplement`、`transfer.fill-result`、`transfer.close` |
| R6 `DATA-OWNER` | ownerBinding 匹配的 Source/Dependency/QualitySnapshot/RecoveryTask | `data-quality.read`、`data-quality.repair`、`data-quality.reconcile`、`quality-fuse.recover`、`platform.read-source`、`sensitive-export.create`、`sensitive-export.download`（高风险动作另过 HRAP，导出仅 owned source） |
| R7 `PLATFORM-OPS` | Runtime/Job/Delivery/Telemetry/Config 技术对象 | `platform.read`、`platform.diagnose`、`platform.retry`、`platform.reconcile`、`role-binding.apply-approved`、`audit.search-technical-metadata`；无业务明细、无自授权 |

RFP→HRAP 的名称映射固定为：`delegation.issue/revoke → temporary-grant.issue/revoke`、`whitelist.change → whitelist.create-or-change`、`bulk.execute → bulk-governance.execute`、Rule 的 `governance.publish/rollback → rule.publish/rollback`、Strategy 的同动作 `→ strategy.publish/rollback`、`governance-action.record → leader-action.record`；`sensitive-export.create/download`、`quality-fuse.recover`、`transfer.submit` 同名映射。需要 HRAP 但无批准映射的动作按 D0 拒绝。

字段类固定为：`B` 基础 ID/状态/时间/版本、`I` 学生直接身份、`C` 联系方式、`S` 敏感关怀属性、`E` 结构化证据/基线/排除、`N` 人工自由文本、`G` 治理汇总、`T` 技术/审计。批准字段摘要矩阵如下（`C=clear`、`M=masked`、`H=hidden`；实际序列化归 1.8）：

| 角色 | B | I | C | S | E | N | G | T |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| R1 | C | C | C | C | C | C | C | M |
| R2 | C | M | H | H | M | H | C | M |
| R3 | C | M | H | M | M | H | C | M |
| R4 | C | H | H | H | H | H | C | M |
| R5 | C | C | C* | C* | M | C* | H | M |
| R6 | C | M† | H | H | C | H | C | C |
| R7 | C | H | H | H | H | H | M | C |

`*` 只允许 TransferOrder 的 purpose/field allowlist 明列字段，否则为 H：C* 全集为 `studentContactPhone|studentContactEmail`，S* 全集为 `referralReasonCode|requestedServiceCode`，N* 全集为 `referralSummary|supplementRequestText|resultSummary`。实际 clear 集合仍取“字段全集 ∩ fieldAllowlist ∩ 当前 purpose/对象授权”；空 purpose、未知字段、诊断/咨询正文、原始证据、网络内容、第三方联系方式和密钥值全局 H。`†` 仅 owned-source 的 SubjectMappingException 修复 purpose 可 clear，否则 masked/hidden。`RFP-FIXTURE-1.0.0` 的 `TRANSFER-A` 只允许 `studentContactPhone`、`requestedServiceCode`、`referralSummary`、`resultSummary` 四项 clear，其余 fixture 列出的 C*/S*/N* 字段与全集外字段均 H。

### AC-1.7-DELEGATION-TOCTOU：委托只收窄且提交前重检

**Given** 对象 scope 由基础授权和已有效 `DelegationGrant` 共同证明，或先前决定携带 relation/grant/policy/objectVersion<br>
**When** `serverNow` 到达 `startAt`/`endAt`，或命令在判定后提交前发生 relation、grant、policy 或 objectVersion 变化<br>
**Then** 有效权限始终为“基础授权 ∩ grant 的对象/动作/字段”，grant 永不扩权；`serverNow == startAt` 生效，`serverNow == endAt` 失效<br>
**And** 写命令在业务提交点用当前权威证据重检；旧决定返回稳定 409 `IDENTITY_AUTHORIZATION_DECISION_STALE`，不提交业务状态且不泄露对象；Grant owner 尚未安装时只返回 none/unavailable 并 fail closed，不创建 3.9c 的生命周期表或命令。

### AC-1.7-IMMEDIATE-REVOCATION：复用 1.6c 且下一请求立即撤权

**Given** 当前账号、组织、任职或责任关系已失效、更正、撤销、到期，或 1.6c invalidation fence 已阻断 lineage<br>
**When** 下一次角色壳、审计检索或对象请求到达任一 Web 节点<br>
**Then** 服务端重新组合 current identity、responsibility scope、可信时间、对象版本与 fence 并拒绝旧 scope，不等待 relay、远程 consumer 或 reconciliation<br>
**And** 1.6c scope DTO 只作为候选 scope evidence，不能单独产生完整 RFP ALLOW；关系失效只移除相应对象 scope，不错误终止全部 SSO，会话/账号撤销仍走既有会话路径。

### AC-1.7-DENY-AUDIT：不泄露拒绝、审计原子性与隐私

**Given** 请求越界、对象不存在、直接深链无权、未知 action、职责冲突、缺策略或授权依赖不可用<br>
**When** 服务端拒绝请求或准备返回敏感内容<br>
**Then** 越界与不存在统一返回 HTTP 404、`IDENTITY_AUTHORIZATION_OBJECT_UNAVAILABLE`、相同 `code/message/traceId/fieldErrors` envelope；无表面权限返回稳定 403，依赖不可证明返回稳定 503，且外部不包含对象类型、存在性、旧责任人、敏感字段名/值/长度或内部 reason<br>
**And** UI 使用“当前职责范围不包含此对象；本次访问已记录”，提供唯一恢复动作；内部 audit 1.4 successor 在内容返回前保存 actor pseudonym、实际 role packages、action、对象 token/digest、policyVersion、scope anchor 摘要、objectVersion、fieldProjectionSummary、result、受信时间和 traceId<br>
**And** 允许、拒绝、依赖失败均可检索；审计不可原子保存时敏感内容不得返回。不得修改冻结的 audit 1.0—1.3 catalog/lock，也不得在 console 或 Toast 中冒充审计。

### AC-1.7-AUTHORIZED-SHELL：独立授权投影与安全客户端状态

**Given** current-session v1 已冻结且前端需要角色菜单/首页<br>
**When** 新增 `GET /api/v1/authorized-shell`（或 Task 1 冻结的等价 URI）并由前端消费<br>
**Then** 响应仅含 schema/policy/version/evaluatedAt、单一 default surface、已授权且安装的 menu/entry capability 和受控依赖状态；不向 current-session v1 塞 roles/menu，不返回可重放的通用 allow token<br>
**And** TanStack Query 使用 `staleTime=0`、仅内存缓存；logout、换号、`auth.changed`、撤权、责任失效和 version change 清除 query、draft 与 shell state 后重取；授权结论不得进入 localStorage、sessionStorage、IndexedDB、Cache Storage、Service Worker 或持久 Pinia<br>
**And** router guard 仅改善导航体验，每个业务 API 仍服务端授权；host bridge 不携带角色、token 或授权结论，深链恢复先回受控 `shell.home` 再重新解析当前默认页。

### AC-1.7-UX-A11Y：真实状态、恢复与可访问角色壳

**Given** 用户处于冷加载、真实空态、筛选无结果、无权限、会话失效、依赖失败/降级或并发失效状态<br>
**When** 角色首页或导航渲染与恢复<br>
**Then** 各状态文案、影响范围和唯一恢复动作明确区分，旧授权/旧菜单不伪装为实时，成功不只用 Toast；重认证返回原目标并重新授权，若目标已失权则保持统一拒绝态<br>
**And** 满足 WCAG 2.2 AA：菜单/动作可键盘访问，Tab 顺序正确，路由后焦点到主标题，浮层关闭焦点返回，动态授权状态使用 live region，状态不只靠颜色，200% 缩放无关键丢失，点击热区至少 40×40 CSS px，不可见字段不进入 DOM/无障碍树<br>
**And** 保持学校红 `#AF251B` 和统一 Element Plus 壳；1440×900、1366×768 无页面级横向滚动，768—1023px 导航抽屉化；小屏不新增独立底部导航或假移动业务页。

## Dev Notes

### 架构不变量与实现指导

- 模块化单体与六边形方向保持 `domain ← application ← adapters`；跨模块只导入 `<module>.api` 或公共事件合同，不跨表、不导入 internal implementation。
- 现有 `AuthorizationRecalculationPort` 只判断会话当前身份/策略新鲜度，供 `CurrentSessionService` 使用；对象授权必须是新的独立端口，不能改变其请求或结果语义。
- `ResponsibilityScopeView` 明确只是 current responsibility scope，不是完整授权。组合器必须再校验 actor、object/action、替代 anchor、RFP/HRAP、policy/objectVersion 和 fence。
- 推荐 `CompositeAuthorizationDecision` 至少包含 `ALLOW | DENY | DEPENDENCY_UNAVAILABLE`、公开安全 reason、内部实际 role packages、命中 scope anchor 摘要、policyVersion、identity/responsibility/invalidation versions、`fieldProjectionSummary`、objectVersion 与 evaluatedAt。对外 DTO 不暴露内部 reason 或原始 anchor 标识。
- 不暴露“任意 object id 能否访问”的生产探测 API；对象 owner 在应用边界调用公共 Java port。`authorized-shell` 只返回导航投影，不是通用 bearer allow token。
- policy catalog 可以按精确 version/digest 缓存；对象级 ALLOW、scope 或字段摘要不能成为跨请求权威缓存。至少两个无状态 web-api 实例必须给出相同判定。
- 任何敏感读、写、导出或序列化 owner 后续都必须使用同一公共 guard；1.7 只实现可复用边界和当前真实调用面，不伪造未来业务 endpoint。
- 高风险 action 仍受 HRAP 审批/有效窗/范围/对象版本约束；RFP ALLOW 不能成为绕过 HRAP 的后门。
