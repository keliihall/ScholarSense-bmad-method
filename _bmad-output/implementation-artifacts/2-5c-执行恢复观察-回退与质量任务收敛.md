## Story

作为数据责任人，
我希望恢复后的质量持续受观察并在恶化时回退，
以便规则只有在完整观察期持续达标并完成最终受控确认后才重新具备资格，且原质量任务、失败回退和外部投递都以唯一、可追溯的事实收敛。

## 业务与交付价值

- 关闭恢复链的最后安全缺口：一次审批或短暂好转不能直接恢复生产，必须以同一 QRP 版本完成连续观察。
- 观察期间任一真实质量失败立即回到 `fused`，更新原 episode/任务并继续阻止新业务对象，不让旧的 eligible 提交覆盖新失败。
- 成功时只关闭 2.5a 创建的同一质量任务；不创建第二任务，不重复关闭，不把投递确认冒充业务完成。
- 以真实 `recoveryCompletedAt` 重新判定窗口可行动性；超过 `latestActionableAt` 的窗口只保留历史证据，永不补发。
- 本 Story 只证明 ingestion-quality 的观察、终态与质量任务 producer 闭环；Story 3.2 的真实消费者、Story 5.5 的公共任务最终 apply、Story 2.7c 的 NFR-8 最终证据和 production-duration 仍不在本 Story 内。

## Story 元数据与实施边界

- **精确基线：** 当前 `main@48b981d`，tree `aeed79a`；Story 2.4/2.5a/2.5b 的交付内容来自 `ac38562`。工作树在创建 Story 前 clean。不得把 2.5b front matter 的开工点 `017997a` 误当 2.5c predecessor。
- **单一 owner：** `ingestion-quality` 是 `QualityEligibility`、active `QualityFuseEpisode`、owner-local `RecoveryTask`、observation/finalization fact 的唯一写入者。不得建立第二套恢复状态机或让适配器直接改业务状态。
- **起点与终点：** 2.5b 成功后全部受影响 eligibility 为 `recovering`，原 task 仍 `open`、episode 仍 active。2.5c 成功原子完成 `recovering -> eligible`、episode close 和同一 task close；观察失败复用既有 `recovering -> fused / RECOVERY_RELAPSED` 路径。
- **QRP 固定值：** 流式源连续 3 批通过并观察 60 分钟；日批源连续 2 批通过并观察 24 小时；补数起点 `max(lastKnownGoodWatermark, trustedNow-90d)` 且全量对账；分层重算 `max(100 个 subject-window，总体不足时全部)`，`mismatch=0`；任一失败或 24 小时内复发回 `fused`。source class 必须来自批准目录/DCC，不得从 UI、频率或默认值猜测。
- **fresh D4：** 2.5b 的 approval receipt 可作为持久前置证据重检，但其 15 分钟 execution lease/JTI 不可复用、续期或重新消费。2.5c 最终提交必须取得绑定当前 actor、对象版本、observation digest 和 `recovering -> eligible` 的 fresh execution confirmation，并在 owner fence 内重检。
- **任务唯一性：** 观察失败更新原 open task；成功关闭原 task。task identity、`workItemKey` 和 generation 不变。task terminal close 后若 24 小时内再复发，由 QFRTP 创建 `generation+1` 的新 episode/task，绝不重开已关闭任务。
- **状态正交：** `QualityEligibility` 是本地业务事实；`TaskDelivery.status` 是独立 transport sidecar。任务关闭/通知/对账失败只令 outbox 重试或 delivery `failed`，不得回滚 eligible、虚构外部已关闭或触发补发。
- **零新业务对象：** `fused|recovering` 期间以及 finalization 自身都不创建 `RuleEvaluation`、`Candidate` 或 `Clue`，不激活 Story 3.2 consumer，不改写既有历史业务对象。
- **最终窗口：** 2.5b preview 不授权最终分类。2.5c 使用可信服务端微秒时间持久化真实 `recoveryCompletedAt`；仅 `recoveryCompletedAt <= latestActionableAt` 标为 `eligible-for-handoff`，晚 1µs 即 `history-only`，不 backfill、不补发。
- **不改 predecessor：** 禁止修改 V000015/V000016/V000020、已锁 QRP/HRAP/PIC/QFTP/QFRTP/handoff、release v1-v8、runtime/roles v1-v5、PAB/dependency locks 的既有字节。新增合同、迁移和 release/runtime/roles 只能 forward/expand successor。
- **证据边界：** DB 行、HTTP 2xx、transport ack、fixture 或短时手动时钟测试不是 production-duration 证明。Story 可声明本地可执行 observation/eligible/task-close 证据，不得声明 FR-12/FR-4/FR-59/NFR-8 已端到端完成。

### 本 Story 包含

1. QRP observation/finalization、fresh D4、task close、episode close、window decision、retention/event/error 的 additive machine-readable successor 与 digest locks。
2. 专用 observation ledger/worker/查询投影：从 2.5b `recoveringStartedAt` 开始持续接收真实、不可变的批次/快照/对账/样本事实，并对 gap、poison、SLO stale、成员或版本漂移失败关闭。
3. 复用既有即时 relapse evaluator；以相同稳定锁序和 optimistic CAS 保证“新失败/新策略胜出”。
4. owner-local finalization 事务：最终 observation decision、全部 eligibility 终态、episode/task close、window decisions、audit、event/outbox、幂等响应和 execution-JTI 全成或全败。
5. 同页 data-quality-panel 的观察/最终确认 UX，以及 contract/domain/MVC/JDBC/PostgreSQL 18.4/并发/授权/隐私/a11y/release 证据。

### 本 Story 不包含

- Story 3.2 的 RuleEvaluation/Candidate/Clue consumer 激活或生产规则消费证明。
- Story 5.5 的公共任务 target/final apply；本 Story 只生产 task close intent 并观察独立 delivery 状态。
- Story 2.7c 的 NFR-8 最终 producer contract suite 或用短时测试冒充生产 60m/24h/24h relapse 运行证据。
- 新建通用任务中心、移动端质量详情页、第二个 recovery task/episode truth、自动重提高风险命令，或从 latest 拼接历史证据。
- 依赖升级、数据库重写迁移、修改 predecessor lock/schema/release 字节。

## Acceptance Criteria

### Epic 原始七条 AC（canonical，逐字保留）

**AC-2.5c-HAPPY** — **Given** 2.5b 已进入 `recovering`，且同一 `QualityRecoveryPolicyVersion` 的 `observationDuration`、失败回退和公共任务契约可用；**When** 数据责任人执行本 Story 主流程；**Then** 连续观察满 `observationDuration` 且质量持续达标后进入 `eligible` 并关闭唯一质量任务；任一条件失败立即回到 `fused` 且更新原任务；**And** 外部失败只改变 `TaskDelivery.status`，不补发失效工作；FR-4/FR-59 最终验收仍归 Story 5.5。

**AC-2.5c-AUTH-DENIAL** — **Given** 操作者不在 `QualityRecoveryPolicyVersion` 的最终确认角色内；**When** 尝试结束 `recovering` 或关闭质量任务；**Then** 拒绝且保持 `recovering/fused` 现状；**And** 不发布 `eligible` 或任务完成事件。

**AC-2.5c-ILLEGAL-STATE** — **Given** `observationDuration` 未满、连续批次中断或样本重算未通过；**When** 尝试从 `recovering` 直接进入 `eligible`；**Then** 拒绝迁移；失败条件成立时回到 `fused`；**And** 原质量任务保持打开并记录具体未满足条件。

**AC-2.5c-BOUNDARY** — **Given** 观察时长、连续通过批次或 `latestActionableAt` 恰在策略边界；**When** 评估最终恢复资格；**Then** 按同一 `QualityRecoveryPolicyVersion` 的含边界定义作出唯一结果；**And** 超出 `latestActionableAt` 的窗口不补发。

**AC-2.5c-DEPENDENCY-FAILURE** — **Given** 质量任务关闭、通知或对账适配器不可用；**When** 本地恢复判定提交；**Then** 本地 `QualityEligibility` 保持真实结果且 outbox 持久重试；**And** `TaskDelivery.status=failed` 不得回滚 `eligible` 或冒充外部已关闭。

**AC-2.5c-IDEMPOTENCY** — **Given** 同一 `recoveryId` 和最终观察水位重放；**When** 再次提交 `eligible` 或 `fused` 结果；**Then** 返回原状态与原质量任务更新版本；**And** 不重复关闭任务、发布事件或补发工作。

**AC-2.5c-CONCURRENCY** — **Given** 最终提交前新批次跌破质量门或策略版本变化；**When** 旧版本尝试进入 `eligible`；**Then** 质量失败/新策略胜出并拒绝旧提交；**And** 规则保持 `fused` 或重新进入受控 `recovering`。

以下 AC 将 canonical 意图投影为可实施约束；冲突时以 canonical AC、批准基线和本 Story 的 owner/失败优先不变量为准。

### AC-2.5c-CONTRACT：additive successor 先冻结 exact 语义（派生 readiness gate）

**Given** predecessor 只支持 `fused -> recovering`、open task 和 2.5c handoff，且现有 `HighRiskApprovalBinding`/task schema/质量任务事件尚不能表达 final eligible/close<br>
**When** Task 0 在编写 DDL、controller 或 UI 前发布 successor<br>
**Then** successor 唯一确定 observation fact/decision、`quality-fuse.recover` 允许的 exact `recovering -> eligible` D4 pair、fresh receipt/lease、same-task close、episode close、final window outcome、24h relapse generation、event/outbox/error/retention 语义<br>
**And** predecessor 字节与原始 handoff immutable bindings 不变；任一 owner、状态对、幂等键或补偿协议仍不唯一时 HALT/correct-course。

### AC-2.5c-OBSERVATION：观察必须由真实持续质量事实构成（派生）

**Given** 2.5b handoff 精确绑定 recovery/eligibility/episode/task/generation、QRP/evidence/preview/rule/member/watermark/approval/lease digests 与 `recoveringStartedAt`<br>
**When** 专用 worker 从不可变 Story 2.3/2.4 事实累计 observation<br>
**Then** 从 owner commit 时刻开始，按 source class 满足完整 60m/24h、流式 3 批/日批 2 批、严格业务序列、required member、质量门、对账与样本要求；无数据、gap、poison、stale、failed 或未知 provider 均不得被当作 pass<br>
**And** observation 只保存版本、摘要、计数、水位、时间和失败原因，不保存学生明文；不复用 `MappingRecomputeJob`，不创建业务对象。

### AC-2.5c-FRESH-D4：最终确认重新授权且令牌单次使用（派生）

**Given** 完整 observation 已形成 immutable decision candidate，2.5b 的 producer approval/token 明确不能跨 24 小时观察窗复用<br>
**When** 系统以当前水位和版本重新生成最终影响预览，当前 final confirmer 再次发起并完成 D4 后执行 `recovering -> eligible`<br>
**Then** runtime 解析当前 QRP 最终确认角色、R6 owned-source 与 business-owner natural-person binding，重新执行 D4 maker/checker 分离，签发绑定当前 object/final preview/observation/policy/member/watermark/auth-generation 的新 approval 与 15 分钟 single-use execution confirmation<br>
**And** 旧 token/JTI、过期 receipt、同一自然人、自报 approval、版本/owner/person 漂移、非全 recovering 或非当前 generation 均 deny；客户端不能提交 trusted timestamps/evidence/receipt/lease。

### AC-2.5c-FINAL-OWNER-TRANSACTION：终态与任务收敛原子化（派生）

**Given** 所有受影响 eligibility 仍为同一 generation 的 `recovering`，observation 与 fresh D4 当前有效<br>
**When** ingestion-quality finalization command 在稳定锁序内提交<br>
**Then** 同一事务写 final observation decision、全部 eligibility=`eligible` history/current、episode closed history/current、同一 task closed history/current、逐窗口 outcome、local audit、monotonic aggregate event/outbox、execution-JTI 与 idempotent response<br>
**And** 任一 eligibility/episode/task/observation/version 不一致全体失败；无网络 I/O、无部分 eligible/close、无第二 task，crash/late rollback 后可安全重试。

### AC-2.5c-FAILURE-WINS：观察失败与最终提交竞争时失败优先（派生）

**Given** final confirmer 读取到通过结果后，新批次、成员、策略、水位、授权或对象版本发生变化<br>
**When** 既有 `QualityFuseTransitionPolicy` 回退与旧 finalization 并发<br>
**Then** 两者使用相同 source-first advisory lock/row-lock/CAS discipline，锁内重读当前事实；真实业务失败或新批准策略先成为 winning fact，旧提交稳定 409/closed deny<br>
**And** `recovering + pass` 仅 preserve，`recovering + verified failure` 回 `fused` 并更新原 open task；technical/provider fault 可重试且不得伪装 business relapse。

### AC-2.5c-WINDOW：真实完成时刻决定 handoff，不补发（派生）

**Given** RuleVersion/window 的 `latestActionableAt` 与 2.5b preview 可用<br>
**When** final owner transaction 以 trusted UTC microsecond time 得到 `recoveryCompletedAt`<br>
**Then** equality 标记 `eligible-for-handoff`，晚 1µs 标记 `history-only`，并保存 rule/window/version/watermark/decision reason/digest<br>
**And** preview 不替代最终判定；两类都不由本 Story 创建 RuleEvaluation/Candidate/Clue、启动 backfill 或补发工作。

### AC-2.5c-TASK-DELIVERY：本地关闭与外部投递正交（派生）

**Given** 本地 finalization 已提交同一 task close intent<br>
**When** PIC adapter、通知、receipt 或 reconcile 暂不可用<br>
**Then** task 本地 closed 与 eligible 保持，outbox/TaskDelivery 独立进入 pending/retrying/failed 并持久重试；transaction 内无网络 I/O<br>
**And** `confirmed` 只表示 transport/外部系统确认，不能冒充公共任务最终 apply；Story 5.5 激活前保持 `runtimeEvidenceClaim=none`。

### AC-2.5c-RELAPSE：终态后的 24h 复发产生新 generation（派生）

**Given** episode/task 已终态关闭且 QRP 24h relapse window 尚未结束<br>
**When** 同一 source/dependency 出现经验证的业务质量失败<br>
**Then** QFRTP 回到 `fused`，创建 `generation+1` 的新 episode/task 并保留与前一 recovery/episode 的审计关联<br>
**And** 不重开、覆写或重新投递已关闭 task，不复用旧 workItemKey/idempotency result；bootstrap/technical gap 不伪装复发。

### AC-2.5c-IDEMPOTENCY：最终水位、close 和 outbox 只发生一次（派生强化）

**Given** 同一 `recoveryId + finalObservationWatermark` 和同一 canonical digest 被 HTTP、worker 或 outbox 重放<br>
**When** 再次提交成功或失败终态<br>
**Then** 返回原 eligibility、episode/task version、window decisions 和 delivery correlation；不新增 history/close/event/work<br>
**And** 同键异 digest 稳定 409，fresh execution JTI 只消费一次；并发不同 key 返回 winning result，不泄露内部 unique-key/锁信息。

### AC-2.5c-API-UX：同页展示观察与诚实状态（派生）

**Given** 已授权 R6 在 desktop/narrow-desktop 的既有 `data-quality-panel` 查看 owned-source task<br>
**When** 查看 observation、失败原因、最终确认与 task delivery<br>
**Then** 同屏显示 QRP version、source class、连续通过计数、已观察/目标时长、失败成员、watermark、`latestActionableAt`、`fused|recovering|eligible`、原 task 和独立 `TaskDelivery`；成功文案区分“本地质量已 eligible”“任务关闭 intent 已提交”“外部投递已确认”<br>
**And** 保留 loading/empty/observing/not-ready/policy-drift/relapsed/ready/finalizing/eligible/history-only/dependency-unavailable/delivery-retrying/failed 状态，错误保留当前会话内 volatile input；identity/offline/unmount/窄屏切换立即 abort/clear，不用 Web Storage/IndexedDB/CacheStorage/SW<br>
**And** 字段错误摘要、首错聚焦、live region、键盘/焦点返回、200% 缩放和状态不只靠颜色；`<768px` 零质量对象请求和零对象 DOM，不新增移动端质量页或通用任务中心。

### AC-2.5c-AUTH-PRIVACY：授权先于对象读取与分页（派生）

**Given** actor 无 owned-source/final-confirm 权限、session/authorization generation 变化或对象不存在<br>
**When** 请求 observation、finalization、task 或冲突结果<br>
**Then** owner-filter 后分页，敏感读取先写最小 audit，返回 concealed 404 或 closed 503/409 envelope；不回显成员、审批人、对象存在性、expected version 或内部失败<br>
**And** HTTP 使用 `credentials: include`、`cache: no-store`、`referrerPolicy: no-referrer`；DTO strict decoder 拒绝未知字段，日志/事件/UI 不含 PII 或高风险 token。

### AC-2.5c-EVIDENCE：全层验证且发布只向前（派生 DoD）

**Given** 本 Story 触及状态机、迁移、D4、事件、任务、API 和 UX<br>

### Architecture Compliance

- 保持模块化单体依赖方向 `domain <- application <- adapters`，跨模块只依赖对方 `.api`；identity-access 负责受信审批/lease，ingestion-quality 只消费公开 port/receipt 并保持质量聚合单写入。
- application command-only、UUIDv7、UTC ISO offset、optimistic concurrency、closed errors、owner-local audit fact、transactional outbox、durable worker fencing 和 monotonic event schema 必须遵守 Architecture Spine。
- 最终事务不跨网络；TaskDelivery/receipt reconcile 是提交后的 side effect。跨 owner lease 协议必须证明 crash、timeout、重复、过期与 late rollback 下不重复执行。
- 事件携带自足 committed facts 与 monotonic `aggregateVersion/routeSequence`，消费者不得回查 latest 补齐历史事件。
