## Story

作为承担任务的用户，
我希望只在当前授权任务期和批准用途内看到完成工作所需的最小字段，
以便在列表、详情、API 和用户界面中安全处理敏感信息，并在任务到期、撤权、策略或密钥变化时立即停止暴露旧权限下的数据。

## 业务与交付价值

- 把 Story 1.7 已计算但尚未执行的 `fieldProjectionSummary` 落为服务端唯一的 C/M/H 字段投影边界，禁止各模块手写删字段逻辑。
- 对 R5 协同人员落实 `purpose × fieldAllowlist × [startAt,endAt) × RFP 封闭全集`，让角色本身不能直接获得敏感内容。
- 以“先授权、再投影、后序列化、审计先于返回”的顺序完成在线敏感读取最小闭环，为 Story 3.10、3.14a—c、4.8 和 7.x 提供可复用公共端口。
- 在本 Story 触及的在线 API、DOM、内存缓存和无障碍树证明明文越权与绕审计成功数为 0；不得借此宣称异步导出文件、下载撤销或全渠道 FR-6/FR-7 已最终关闭。

## Acceptance Criteria

### AC-1.8-HAPPY：七角色、任务期与全渠道最小投影（受控原始 AC）

**Given** `RFP-FIXTURE-1.0.0` 的七角色与 B/I/C/S/E/N/G/T 期望表，`TRANSFER-A.fieldAllowlist = studentContactPhone,requestedServiceCode,referralSummary,resultSummary`、R5 星号字段封闭全集、R6 owned-source 例外及全局禁止字段<br>
**When** 服务端在列表、详情、API、异步导出 conformance sink、DOM、缓存与无障碍树执行 C/M/H 投影，并在每次序列化以及后续下载端口调用前重检 policy/scope/objectVersion/keyVersion<br>
**Then** CLEAR 仅含批准最小 schema；R5 对 `TRANSFER-A` 仅上述四个字段 clear，`studentContactEmail`、`referralReasonCode`、`supplementRequestText`、封闭全集外字段和 `TRANSFER-B` 全部 hidden；MASKED 使用与原值长度无关的固定替代，HIDDEN 同时省略键、值和长度；诊断/咨询正文、原始证据、网络内容、第三方联系方式与密钥值始终 hidden<br>
**And** purpose 失配、`serverNow == endAt`、策略/密钥/IAM/可信时间不可用、字段或版本未知、并发撤权均 fail closed；不缓存旧权限、不降级明文，JSON 与导出 conformance sink 使用同一投影 oracle；真实异步导出/下载运行能力仍按本 Story 的范围解释留给 3.14a—c。

### AC-1.8-CONTRACT：字段 schema、C/M/H 和 successor lock 不可漂移

**Given** 构建、启动或投影请求加载字段投影合同<br>
**When** 校验 `schemaVersion`、`RoleFieldPolicyVersion`、字段名→B/I/C/S/E/N/G/T 映射、对象适用字段、固定 mask token、全局 H 集、R5/R6 条件和 fixture digest<br>
**Then** 只接受批准且机器可验证的精确版本；未知对象、字段、字段类、策略、purpose、mask profile 或 digest 均按 HIDDEN/整体 fail closed，绝不采用“默认 clear”<br>
**And** 新合同位于独立 successor 包并由 release manifest 精确绑定；Story 1.7 和 audit 1.0—1.4 的冻结文件及 digest 字节不变；合同 checker 同时验证 JSON 与导出 sink 的键集合、mask 值和错误 envelope。

批准字段规则：

| 角色 | B | I | C | S | E | N | G | T |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| R1 | C | C | C | C | C | C | C | M |
| R2 | C | M | H | H | M | H | C | M |
| R3 | C | M | H | M | M | H | C | M |
| R4 | C | H | H | H | H | H | C | M |
| R5 | C | C | C* | C* | M | C* | H | M |
| R6 | C | M† | H | H | C | H | C | C |
| R7 | C | H | H | H | H | H | M | C |

- R5 封闭全集：C*=`studentContactPhone|studentContactEmail`；S*=`referralReasonCode|requestedServiceCode`；N*=`referralSummary|supplementRequestText|resultSummary`。最终 CLEAR = 封闭全集 ∩ 当前对象批准 schema ∩ 当前 `fieldAllowlist` ∩ 当前 purpose ∩ 有效任务窗 ∩ 基础授权/DelegationGrant 字段交集；任一不可证明即 HIDDEN。
- R6 `I†` 只在 owned-source 且 `SubjectMappingException` 修复 purpose 时可 CLEAR；其他 purpose 服从批准的 masked/hidden 结果，不得将“数据 owner”解释为全库明文。
- 全局 H：诊断/咨询正文、量表或原始证据正文、网络内容、第三方联系方式、密钥/令牌值；即使字段名误归类为 C 或角色矩阵为 CLEAR，也必须 HIDDEN。
- HIDDEN 不产生键、值、`null`、占位、长度、accessible name 或“存在但无权”的信号；MASKED 使用按语义字段类型冻结的固定常量，不随原值、空值、字符集或长度变化。

### AC-1.8-SERVER-PROJECTION：只从安全 DTO 投影，序列化器不得成为权限边界

**Given** 对象 owner 返回受控字段描述、密文/安全值引用和 Story 1.7 的当前对象授权请求<br>
**When** 应用服务准备在线响应或导出 conformance 输出<br>
**Then** 顺序固定为：current composite authorization → 读取批准字段描述/值引用 → 序列化前 current recheck → 计算逐字段 C/M/H → 仅解密最终 CLEAR → 从允许键构造新的不可变最小 DTO → 持久化敏感读取审计 → 序列化返回<br>
**And** HIDDEN/MASKED 字段不触发解密；投影复杂度对字段数线性，字段顺序和输出 schema 确定；Jackson/controller/前端不得通过 `@JsonIgnore`、动态删键、CSS 隐藏或模板条件承担最终授权<br>
**And** owner 只能通过模块公共 application port 调用投影；`identity-access` 不反向 import 业务模块 internal 包，跨模块依赖保持 `domain ← application ← adapters` 和仅 `<module>.api` 可导入规则。

### AC-1.8-TASK-WINDOW：任务 purpose、allowlist、半开窗口和 grant 只收窄

**Given** R5/R2 或携带 DelegationGrant 的个体字段请求<br>
**When** `serverNow` 位于任务开始前、恰好开始、有效窗内、恰好结束或结束后，或 purpose/allowlist/workItem/grant 字段发生变化<br>
**Then** `[startAt,endAt)` 精确成立：开始边界包含、结束边界排除；R2 个体读取必须有显式当前 workItem；R5 必须是当前分配 Transfer、purpose 匹配且窗内；角色包本身不能替代这些条件<br>
**And** DelegationGrant 的字段集合始终与基础授权、RFP、对象 schema 和任务 allowlist 求交，永不扩权；空/重复/大小写变体/未知字段、客户端提交的 purpose 或 allowlist 不产生权限<br>
**And** 到期、关闭、撤权、登出、换号、责任关系失效、objectVersion/policyVersion/keyVersion 变化后，下一请求和当前序列化前立即拒绝旧字段；不等待缓存过期、relay 或定时调度。

### AC-1.8-CRYPTO：受控解密、密文绑定和轮换 fail closed

**Given** 最终 CLEAR 字段的存储值为带 `keyRef/keyVersion` 的密文<br>
**When** 投影边界请求解密或密钥轮换窗口同时存在旧/新版本<br>
**Then** `CryptoPort` 调用包含 actor/service identity、classification、purpose、keyRef/keyVersion、environment、aggregate/object identity、field identity、traceId；AAD 绑定环境+对象+字段，跨对象/字段替换、错误 keyRef/version 或篡改密文全部失败关闭<br>
**And** 轮换采用 dual-read/new-write：已批准旧版本可读，新写只用当前版本；current key version 在序列化前重检，KMS unavailable/timeout/unknown version 不返回内容、不回退旧明文或本地默认密钥<br>
**And** 明文只在最短受控作用域存在；可擦除缓冲在 `finally` 清零，禁止出现在异常、日志、metrics、trace、事件、outbox、读模型、缓存、审计 payload 或测试快照；Java `String` 不得被当作“可保证擦除”的长期容器。

### AC-1.8-TOCTOU-AUDIT：并发撤权与审计提交先于内容

**Given** 首次授权后、内容序列化前发生 relation/grant/task/purpose/allowlist/objectVersion/policyVersion/keyVersion 任一变化，或敏感读取审计持久化失败<br>
**When** current recheck 比较 Story 1.7 决定 token 与当前证据并准备返回内容<br>
**Then** 任一变化返回稳定 stale/依赖失败 envelope，响应体中不存在投影字段；不得从之前查询结果、query cache、序列化缓冲或重试路径返回旧内容<br>
**And** 允许、拒绝、依赖失败记录 actor pseudonym、实际 role packages、action/object token、purpose 摘要、policy/schema/object/key version、字段类和 C/M/H 数量摘要、result、trusted time、traceId，但不记录敏感字段名清单、值或长度<br>
**And** 审计写入与“允许内容可返回”处于可证明的事务边界；审计 rollback/timeout 时内容不返回。复用现有 `SensitiveReadTransactionPort`/等价 Spring `TransactionTemplate` 适配器，不以异步日志或 Toast 冒充审计成功。

### AC-1.8-AUDIT-SEARCH：现有生产页面接入公共投影且行为不退化

**Given** `audit-operations` 已有真实 R3/R7 授权搜索、快照分页、tokenized 条件、手工 `AuditFieldVisibility`/`AuditSearchDecisionValidator` 和 `AuditSearchView`
**When** 本 Story 集成公共字段投影<br>
**Then** R3 仅获得批准的业务元数据最小 schema，R7 仅获得批准的技术元数据最小 schema；重复手工字段矩阵被公共 RFP 投影替代或降为对象字段 catalog，不能出现两个冲突 oracle<br>
**And** 保持现有 snapshot/cursor 一致性、稳定排序、参数化 SQL、过滤 tokenization、越界/不存在等价语义、审计先于返回、`Cache-Control: no-store` 和既有错误 envelope；默认不新增表或 migration<br>
**And** API 原始 JSON 字节、Jackson DTO、前端 TypeScript schema、表格列、CSV-like conformance sink 与无障碍树使用同一批准键集合；未知/额外服务端字段不能因前端忽略而被视为安全。

### AC-1.8-CLIENT-A11Y：浏览器缓存、DOM 和无障碍树不泄露

**Given** 用户浏览审计检索或后续消费者渲染 CLEAR/MASKED/HIDDEN 字段，并可能发生撤权、换号、会话失效、依赖/密钥失败或后台 refetch<br>
**When** Vue/TanStack Query 接收、缓存、更新和卸载投影结果<br>
**Then** query 使用稳定 key、`staleTime=0`、敏感 query 的 `gcTime=0`（或经测试证明等效的立即 remove）、仅内存存活；logout、换号、`auth.changed`、授权/策略/密钥版本变化、路由离开和失败响应清除旧结果，不进入 localStorage、sessionStorage、IndexedDB、Cache Storage、Service Worker 或持久 Pinia<br>
**And** HIDDEN 字段在 response、query data、DOM attribute/text/comment、开发模式状态和 accessibility tree 中均不存在；MASKED 视觉值为固定 token，无障碍名称只表达“已脱敏”，不朗读星号个数、原长度或字段存在原因<br>
**And** 加载、真实空态、无权限、策略/密钥不可用、并发失效均显示不泄露的稳定状态和唯一恢复动作；后台错误不保留旧敏感表格伪装成功；键盘、焦点、live region、200% 缩放、375px/768px/1366×768/1440×900 和 axe-core 检查通过。

### AC-1.8-PRIVACY-ERRORS：失败语义和遥测不泄露

**Given** 字段/对象未知、purpose 不匹配、依赖失败、解密失败、序列化异常、取消请求或恶意输入包含敏感文本<br>
**When** API、日志、metrics、trace、异常处理与 UI 处理失败<br>
**Then** 外部只返回稳定 status/code/message/traceId/fieldErrors envelope；对象越界与不存在不可区分，错误不得包含字段是否存在、字段名清单、值、长度、keyRef、KMS 内部信息、对象 owner 或旧权限<br>
**And** telemetry 仅使用受控低基数 code、object class、result、policy/schema/key version 与计数，不使用 studentId、objectId、purpose 自由文本、field name/value、evidence body 或 trace baggage 敏感内容<br>

## Dev Notes

### 先复用的 Story 1.7 能力

- `RoleFieldPolicyCatalog` 已冻结七角色、字段类矩阵和 R5 条件字段集合；本 Story应扩展“实际字段名→字段类/对象 schema”的 successor catalog，不复制角色矩阵。
- `CompositeAuthorizationEvaluator` 已输出 `fieldProjectionSummary` 与 `clearConditionalFields`；它不执行序列化。实际投影必须消费其当前决定并在序列化前用 `CompositeAuthorizationRecheckAdapter` 重检完整 token。
- `CurrentEvidenceCompositeAuthorizationAdapter` 已逐请求读取 identity/responsibility/object owner/fence/trusted time 并 fail closed；继续使用这一 current-evidence 路径，不建允许决定缓存。
- `AuthorizationObjectEvidence` 已承载 purpose、fieldAllowlist、任务窗、object/policy/evidence version 和 delegation；这些字段来自 owner 证据，不信任浏览器请求。
- `SensitiveReadTransactionPort` 与 JDBC/Spring 适配器已经存在；优先复用以实现 audit-before-return，不再创建平行事务抽象。
- 现有通用 `EnvelopeEncryptionPort/DecryptionPort` 面向 identity session/archive/token custody，context 不足以满足 AD-9；字段 crypto 必须有独立、完整的调用上下文。

### 实现顺序与安全不变量

1. **字段 catalog 是 allowlist。** 只有对象 owner 注册且合同锁定的字段才可进入 projector；反射、Bean introspection、任意 Map 键遍历不能扩大输出。
2. **授权早于读取，投影早于序列化。** 能不读取的敏感值就不读取；H/M 不解密；安全 DTO 是序列化器唯一输入。
3. **current recheck 紧贴序列化。** 首次授权不能替代最终检查；policy/scope/object/key 任一版本变化都丢弃已准备内容。
4. **HIDDEN 是不存在。** 不返回 null/空串/`***`、元数据或 accessible label；MASKED 才允许固定 token，并且 token 长度与原值无关。
5. **审计先提交。** 内容只能在敏感读事务成功后离开应用边界；审计仅存摘要和版本，不存字段值/长度/敏感字段名清单。
6. **缓存不是授权。** 后端不缓存 allow；前端敏感 query 立即 stale/立即回收，任何身份或版本变化先清旧数据再重取。
7. **RS 只做版本绑定。** 本 Story 没有新生产数据类或导出文件，不执行 Story 6.6 的删除/备份证明；若新增持久对象，必须先绑定 RS-1.0.0 并扩大 Story 审查范围。

### 技术栈与版本约束

- 严格使用 ADR/PAB 固定版本：JDK 25、Spring Boot 4.1.0/Spring Framework 7.0.8、PostgreSQL 18.4；Vue 3.5.40、TanStack Vue Query 5.101.2、TypeScript 6.0.2、Vite 8.1.5、Vitest 4.1.10、Playwright 1.61.1、axe-core 4.12.1。不得为本 Story 升级、降级或引入另一套权限/序列化/缓存框架。
- 官方 Spring Boot 4.1.0 文档确认其支持 Java 17—26，JDK 25 在支持范围内；无需以“兼容修复”为由更换基线。
- 当前项目是 imperative Spring MVC/JDBC；审计原子性继续采用 `TransactionTemplate`/既有事务 port，不引入 reactive transaction。
- TanStack Query v5 默认 inactive query 会保留 5 分钟；敏感投影不得依赖默认值，必须显式 `gcTime=0` 或经测试证明等效的立即清除。
- Java 可擦除缓冲使用 `char[]`/`byte[]` 并在 `finally` 中 `Arrays.fill`；这降低驻留窗口但不是完整内存取证保证，验收重点仍是最小解密、禁止跨边界复制和零明文持久/遥测。

### 性能、可靠性与可观测性

- projector 应是 O(n fields) 且确定性；对 H/M 禁止 KMS 调用，避免逐字段重复授权查询。若批量详情需要批量解密，由端口批处理但每项保持完整 context/AAD 和输出 allowlist。
- 不将学生标识、对象 ID、字段名/值或 purpose 自由文本作为 metric label；只用稳定低基数 result/code/version/objectClass 和 C/M/H count。
- 取消、客户端断连或 serializer 异常同样必须擦除临时明文；已写入 socket 的部分响应不可通过事后 rollback 撤回，因此在确认审计成功与最终 recheck 前不得开始 streaming 敏感响应。
- 禁止对敏感 JSON/导出使用无界 streaming；后续大文件导出由 3.14b 设计受控 spool/object storage，不在本 Story 通过响应流提前实现。
